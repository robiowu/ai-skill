# Skill 评估检查清单

> Stage 3 整体评估的完整检查清单和评分细则。

---

## 维度 1: 结构审查（6 项）

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 1.1 | SKILL.md 是否存在且非空 | 文件存在且内容 > 0 字节 | Error |
| 1.2 | frontmatter 是否包含 name | `name:` 字段存在且非空 | Error |
| 1.3 | frontmatter 是否包含 description | `description:` 字段存在且非空 | Error |
| 1.4 | description 是否有效 | 非空、非模板占位符（如"待补充"）、含触发关键词、20-200 字 | Warning |
| 1.5 | 是否包含执行流程 | 有编号的 Phase/Step 划分 | Warning |
| 1.6 | 是否有参考文件索引 | 有指向 references/ scripts/ cases/ 的索引表 | Warning |

---

## 维度 2: 目录审查（4 项）

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 2.1 | 目录结构是否合规 | 目录结构是否匹配声明的 skill 类型模板（见 `skill-types.md`） | Warning |
| 2.2 | references/ 是否有死文件 | `references/` 中的文件是否都在 SKILL.md 中被引用 | Info |
| 2.3 | scripts/ 是否有 requirements.txt | 如有 `scripts/` 目录，是否含 `requirements.txt` | Info |
| 2.4 | 是否有 README.md | 人类可读文档是否存在 | Info |

---

## 维度 3: 内容审查（4 项）

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 3.1 | SKILL.md 是否过长 | 行数 < 400（超标应外置到 references/） | Warning |
| 3.2 | 是否内嵌大段代码 | 是否有 > 20 行的代码块（应在 scripts/ 中） | Warning |
| 3.3 | 降级声明是否具体 | 降级行为是否明确到步骤级别（非笼统的"跳过"） | Error |
| 3.4 | 步骤间输入/输出是否声明 | 每步是否有明确的输入数据和输出格式描述 | Warning |

---

## 维度 4: 安全审查（3 项）

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 4.1 | 是否包含硬编码密钥 | grep `token` `password` `secret` `api_key` `-----BEGIN` 等关键词 | Error |
| 4.2 | 是否包含任意命令执行 | 有无 `eval` `exec` `os.system(用户输入)` 等危险模式 | Error |
| 4.3 | 是否有破坏性操作警告 | 涉及 `rm -rf` `DROP TABLE` `force push` 等操作是否有前置确认 | Warning |

---

## 维度 5: 完备性审查（4 项）

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 5.1 | 是否有错误处理/降级路径 | 每个外部依赖是否定义了不可用时的 fallback | Error |
| 5.2 | Generator 型是否有自校验 | Generator 型是否在输出步骤后有复核步骤 | Error |
| 5.3 | Reviewer 型是否有评分公式 | Reviewer 型是否有可复现的评分公式 | Warning |
| 5.4 | Case-Driven 型是否有 cases/README.md | case 目录是否存在 README.md | Error |

---

## 维度 6: 复杂流程分治评估（4 项，条件适用）

> 仅当 skill 在实现阶段启用了 subagent/md 追踪时执行此维度。否则全部 N/A。

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|----------|:------:|
| 6.1 | subagent 拆解是否合理 | 子任务是否有独立输入/输出契约、无重叠探索区域 | Warning |
| 6.2 | progress.md 模板是否完整 | 是否包含：执行清单 + 进度标记 + 决策记录 + 中间结果摘要 | Warning |
| 6.3 | 子任务间依赖是否清晰 | 依赖关系是否声明、无循环依赖 | Error |
| 6.4 | 主线恢复流程是否完整 | SKILL.md 中是否定义了从 progress.md 恢复的流程 | Warning |

## 评分规则

### 机械评分

- 起始: **10 分**
- 每项 Error: **-2 分**
- 每项 Warning: **-0.5 分**
- Info 项: 不扣分
- N/A 项: 不计入分母
- 底线: **1 分**

### 定性调整

在机械分基础上 ±1 分：
- **+1**: 设计特别精妙、文档特别完整、有独特的创新点
- **-1**: 整体混乱、多处不一致、有根本性设计缺陷未被检查项覆盖

### 分数段含义

| 分数 | 评价 | 建议 |
|:----:|------|------|
| 8-10 | 🟢 生产就绪 | 可以直接使用 |
| 5-7 | 🟡 可用但需改进 | 建议修复 Warning 项后使用 |
| 1-4 | 🔴 需大幅修改 | 存在阻塞性 Error，不建议直接使用 |

---

## 严重度定义

| 级别 | 标记 | 含义 | 典型场景 |
|------|:----:|------|----------|
| Error | 🔴 | 阻塞性问题，必须修复 | 缺少 name、硬编码密钥、无降级路径 |
| Warning | 🟡 | 偏离最佳实践，建议修复 | SKILL.md 过长、描述不准确 |
| Info | 🔵 | 优化建议，锦上添花 | 缺少 README、可增加索引 |
