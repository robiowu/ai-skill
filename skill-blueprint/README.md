# Skill Blueprint — Skill 全生命周期管理

一个覆盖 skill **设计 → 实现 → 评估** 三阶段的元 Skill。提取自 `skill-creator`、`skill-checker`、`diffscope` 等成熟 skill 的设计实践。

## 定位

```
skill-blueprint（本 skill）覆盖全流程:
① 蓝图设计 → 架构是否合理？类型归属？范式对齐？
② 落地实现 → 文件编写、测试迭代、打包发布
③ 整体评估 → 执行层面审查、质量评分、改进建议
```

三阶段可灵活切换——根据用户输入和当前进度智能判断所处阶段，支持评估不通过后回到实现阶段修复。

## 触发方式

在 AI 助手中提及以下关键词时自动激活：
- "设计一个 skill"、"创建 skill"、"skill 架构"
- "skill 最佳实践"、"skill 规范"、"skill 范式"
- "审查 skill 设计"、"skill 设计是否合理"
- "帮我规范化这个 skill"
- "实现 skill"、"编写 skill"、"打包 skill"
- "评估 skill"、"审查 skill 质量"

## 三阶段

| 阶段 | 目标 | 核心活动 | 产出物 |
|------|------|----------|--------|
| Stage 1: 蓝图设计 | 确定架构方向 | 类型识别 → 范式审查 → 设计评分 → 模板推荐 | 设计审查报告 |
| Stage 2: 落地实现 | 产出可用 skill | 文件编写 → 测试验证 → 迭代改进 → 打包 | 完整 skill 目录 |
| Stage 3: 整体评估 | 质量把关 | 结构/内容/安全/完备性审查 → 评分 | 评估报告 |

## 9 条核心设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | 步骤分离 | 每步有编号、门控、输入/输出声明 |
| 2 | 功能独立 | 脚本处理确定性任务，AI 处理推理判断 |
| 3 | 一致性校验 | 输出步骤配复核步骤，主动找反证 |
| 4 | 过程可量化 | 断言 + 评分 + 基准，为改进提供方向 |
| 5 | 评估规则化 | 检查清单可操作，严重度可分级 |
| 6 | 降级必有路 | 每个外部依赖定义 fallback 路径 |
| 7 | 知识案例化 | 经验沉淀为触发模式 + 检查规则 |
| 8 | 反模式自检 | 执行中对照反模式表，主动纠偏 |
| 9 | 复杂流程分治 | 大批量强流程任务使用 subagent + md 追踪进度 |

**原则 9** 是 v2 新增：当被设计 skill 涉及 ≥5 个串行步骤、大量中间数据、且不适合纯脚本固化时，应纳入 subagent 拆解和本地 md 进度追踪机制，避免 token 过长、幻觉和注意力丢失。

## 设计审查维度（Stage 1）

| 维度 | 检查项 | 关注点 |
|------|:------:|--------|
| 结构合规性 | 4 | 步骤是否分离、是否有门控标记、粒度是否适中 |
| 脚本分离度 | 3 | 确定性任务是否脚本化、脚本是否独立可测 |
| 自校验机制 | 3 | 输出步骤后是否有复核、复核是否"找反证" |
| 降级健壮性 | 3 | 外部依赖是否有降级声明、降级是否明确 |
| 知识可沉淀性 | 3 | 是否有案例机制、触发模式是否可匹配 |

评分采用 10 分制：起始 10 分，设计缺陷 -2 分，设计偏离 -0.5 分，底线 1 分。

## 评估审查维度（Stage 3）

| 维度 | 检查项 | 关注点 |
|------|:------:|--------|
| 结构审查 | 6 | SKILL.md 存在性、frontmatter 完整性、描述有效性 |
| 目录审查 | 4 | 目录合规性、死文件、依赖声明、README |
| 内容审查 | 4 | 长度控制、代码外置、降级具体性、输入输出声明 |
| 安全审查 | 3 | 硬编码密钥、任意命令执行、破坏性操作 |
| 完备性审查 | 4 | 降级路径、自校验、评分公式、案例 README |
| 复杂流程分治 | 4（条件） | subagent 合理性、progress.md 模板、依赖清晰性 |

## 快速开始

1. 在 AI 助手中描述你的 skill 想法 → skill-blueprint 自动激活
2. Stage 1：识别 skill 类型，审查架构设计，输出评分
3. Stage 2：按推荐模板创建文件，编写 SKILL.md，测试迭代
4. Stage 3：执行层面审查，输出评估报告
5. 根据评估结果修复 → 重新评估 → 交付使用
