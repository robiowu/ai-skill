# Skill Blueprint — Skill 设计范式与最佳实践

一个用于审查 skill 架构设计的**元 Skill**，提取自 `skill-creator`、`skill-checker`、`diffscope` 等成熟 skill 的设计实践。

## 定位

```
① skill-blueprint（本 skill）→ 设计阶段：架构是否合理？
② skill-creator            → 实现阶段：编写、测试、迭代、打包
③ skill-checker            → 审查阶段：格式、安全、完整性审查
```

- **skill-blueprint 做什么**：审查 skill 的类型归属、目录结构、步骤分离、降级路径、自校验机制等设计层面
- **skill-blueprint 不做什么**：编写代码、运行测试、打包文件——这些是 skill-creator 的工作
- **设计审查完成后**：输出"设计已就绪，建议使用 `skill-creator` 进入实现阶段"

## 触发方式

在 AI 助手中提及以下关键词时自动激活：
- "设计一个 skill"、"创建 skill"、"skill 架构"
- "skill 最佳实践"、"skill 规范"、"skill 范式"
- "审查 skill 设计"、"skill 设计是否合理"
- "帮我规范化这个 skill"

## 审查维度

skill-blueprint 从 5 个维度审查 skill 设计：

| 维度 | 检查项 | 关注点 |
|------|:------:|--------|
| 结构合规性 | 4 | 步骤是否分离、是否有门控标记、粒度是否适中 |
| 脚本分离度 | 3 | 确定性任务是否脚本化、脚本是否独立可测 |
| 自校验机制 | 3 | 输出步骤后是否有复核、复核是否"找反证" |
| 降级健壮性 | 3 | 外部依赖是否有降级声明、降级是否明确 |
| 知识可沉淀性 | 3 | 是否有案例机制、触发模式是否可匹配 |

评分采用 10 分制：起始 10 分，设计缺陷 -2 分，设计偏离 -0.5 分，底线 1 分。

## 8 条核心设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | 步骤分离 | 每步有编号、门控、输入/输出声明 |
| 2 | 功能独立 | 脚本处理确定性任务，AI 处理推理判断 |
| 3 | 一致性校验 | 输出步骤配复核步骤，主动找反证 |
| 4 | 过程可量化 | 断言 + 评分 + 基准，为改进提供方向 |
| 5 | 评估规则化 | 检查清单可操作，严重度可分级 |
| 6 | 降级必有路 | 每个外部依赖定义 fallback 路径 |
| 7 | 知识案例化 | 经验沉淀为触发模式 + 检查规则 |
| 8 | 反模式自检 | 执行中对照反模式表，主动纠偏 |

## 目录结构

```
skill-blueprint/
├── SKILL.md                              # AI 执行指令（<200 行）
├── README.md                             # 本文档
└── references/                           # 参考资料
    ├── skill-types.md                    # 5 种类型完整模板
    ├── design-patterns.md                # 8 条原则深入解析
    ├── checklist-design.md               # 16 项设计审查检查清单
    └── anti-patterns.md                  # 8 条常见反模式 + 纠偏
```

> skill-blueprint 自身不含 `scripts/`、`cases/`、`assets/`——它是纯审查指导型 skill，不产生文件输出。

## 设计溯源

本 skill 的设计范式提取自以下源头：

| 源头 | 提取的范式 |
|------|-----------|
| **skill-creator** | 渐进式加载、核心循环（草稿→测试→评审→改进）、可量化评估、描述优化 |
| **skill-checker** | 5 维度检查清单、严重度分级（Error/Warning/Info）、10 分制评分 |
| **diffscope** | 12 步工作流门控、降级处理、案例库驱动、自我复核、时间盒约束 |
| **diffscope 案例库** | 触发模式匹配（可机械匹配）、可操作检查规则（找到 X → 比对 Y → 判断 Z） |

## 快速开始

1. 在 AI 助手中描述你的 skill 想法
2. skill-blueprint 自动激活，识别 skill 类型并审查设计
3. 根据审查建议调整设计
4. 使用 `skill-creator` 进入实现阶段
5. 实现完成后用 `skill-checker` 进行执行层面审查
