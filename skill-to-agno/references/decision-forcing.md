# 决策推动清单

每个 Stage 遇到架构分叉点时，必须使用 `ask_user_question` 向用户确认。不自行做决策。

---

## Stage 1：信息采集

| # | 决策项 | 追问 | 默认值 | 触发条件 |
|---|--------|------|--------|----------|
| 1.1 | **项目名称** | 输出 agno 项目的目录名/文件名前缀？ | skill 目录名（kebab-case） | 分析完 skill 目录后 |
| 1.2 | **是否支持 HITL** | 是否需要暂停-续跑能力？（AgentOS UI 交互式问答） | skill 涉及 question 工具 → 是；否则 → 否 | 分析完 SKILL.md 后 |
| 1.3 | **是否需要 agents/*.md** | 是否生成 codemaker agent 配置文件？ | 是 | HITL 决策确认后 |
| 1.4 | **目标端口** | AgentOS HTTP 服务监听哪个端口？ | 7777 | HITL 决策确认后 |
| 1.5 | **数据目录** | 数据库文件和临时数据放在哪里？ | `tmp/` | 端口确认后 |
| 1.6 | **使用的模型** | model_id 和 provider_id？（⚠️ 实际路由由 codemaker API 网关决定，此值仅作请求参数） | 当前项目 `.env` 中的配置 | 数据目录确认后 |

### 决策 1.2 细化规则

| Skill 特征 | HITL 默认值 | 原因 |
|------------|:-----------:|------|
| SKILL.md 中有 `question` 工具调用 | **是** | 审查类 skill 需用户确认维度/补全信息 |
| 无 question 工具，但需要用户输入（如文件路径） | **是** | 用户需提供输入 |
| 纯自动生成类 skill | **否** | 无需用户交互 |

## Stage 2：代码生成

| # | 决策项 | 追问 | 默认值 |
|---|--------|------|--------|
| 2.1 | **agent 类名** | Agent 类的 Python 类名？ | `{Name}Agent`（PascalCase） |
| 2.2 | **agent id** | AgentOS 数字员工 ID？ | 项目名（kebab-case） |
| 2.3 | **agent 显示名称** | AgentOS UI 中显示的名称？ | skill 的 description 首句 |
| 2.4 | **是否需要日志** | 是否在 agent 类中加入请求生命周期日志？ | 是（参考 add-agent-request-logging 变更） |

---

## Stage 3：入口与配置

此阶段无新决策点——所有参数从 Stage 1 + Stage 2 继承。

| 占位符 | 来源 |
|--------|------|
| `<name>` | Stage 1 的项目名称 |
| `<Agent 类名>` | Stage 2 的 agent 类名 |
| `<model_id>` | Stage 1 的模型决策 |
| `<port>` | Stage 1 的端口决策 |
| `<data_dir>` | Stage 1 的数据目录决策 |

|---|--------|------|--------|
| 4.1 | **是否运行验证** | 是否现在启动 start.bat 验证 AgentOS？ | **是** |

## 通信规范

1. **每次最多问 2 个问题**（避免选项太多导致 UI 混乱）
2. **每个问题提供默认值**并标注"(Recommended)"
3. **提供简短说明**帮助用户理解每个选项的含义
4. **用户选择"Other"时**——允许自由输入
5. **所有确认结果写入 progress.md**
